Structured Safety, Zero Guesswork

Raw shell generation without validation is unpredictable. HASSHR protects your operating system with four deterministic boundaries[cite: 1].

Deterministic Guardrails

Every proposed command is validated with pipeline-aware AST and shlex analyzers[cite: 1]. Destructive actions like rm -rf / are hard-blocked unconditionally[cite: 1].

Change Journal & Rollback

Every file alteration, configuration edit, or moved item writes to an append-only change journal with SHA-256 diffs[cite: 1]. Undo reversible steps cleanly[cite: 1].

Planner-Verifier Loop

The planner, risk classifier, executor, and verifier are strictly separated[cite: 1]. The agent never declares a task done until state verification succeeds[cite: 1].

Configurable Autonomy Modes

You control how much authority the agent possesses. Toggle anytime via /mode[cite: 1].

Default

ask-sensitive

Safe reads and routine file operations run without friction[cite: 1]. Sudo, package management, kernel flags, and disk operations require explicit confirmation[cite: 1].

Recommended balance for developers and daily work[cite: 1].

ask-all

Total oversight. Read-only commands run automatically, while every state-altering write, move, or config change requires your approval[cite: 1].

Ideal for non-programmers and critical environments[cite: 1].

auto

Headless speed. Runs end-to-end plans without prompting. Hard-blocked destructive operations remain blocked[cite: 1].

Tailored for CI pipelines and sandbox environments[cite: 1].
Diagnostics Engine

Troubleshooting Cases: Guided Trial & Error

When hardware, drivers, or system services fail, HASSHR initiates an isolated, stateful Case with structured rollback[cite: 1]:

  • 1 Pre-Flight Success Test: Agrees on a measurable pass/fail test before any change is attempted[cite: 1].
  • 2 Isolated Hypotheses: Attempts fixes one at a time[cite: 1]. Failed attempts are automatically rolled back before testing the next[cite: 1].
  • 3 Clean-Room Verification: Reverts all experimental steps once a solution is found and reapplies only the winning change[cite: 1].
  • 4 Candid Reporting: Distinguishes verified fixes from workarounds and known upstream kernel regressions[cite: 1].
