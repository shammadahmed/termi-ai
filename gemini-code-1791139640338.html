Built for Safety. Not Guesswork.

Most terminal tools run raw commands generated by LLMs without validation. TermiAI wraps machine execution in four discrete safety layers.

Deterministic Risk Engine

Commands are parsed via AST & shlex outside the LLM. Destructive actions (rm -rf /, mkfs) are hard-blocked unconditionally.

Atomic Change Journal

Every config edit, folder move, or package adjustment records SHA-256 diffs and snapshots. If something doesn't work, roll it back with one command.

Multi-Agent Verification

Execution is split between Planner, Risk, Executor, and Verifier agents. Steps aren't marked complete until target state is confirmed.

Granular Permission Modes

You control the autonomy dial. Switch modes on the fly using /mode.

Default

ask-sensitive

Safe & moderate operations run automatically. State-altering tasks (sudo, package installs, grub, disk changes) halt for explicit approval.

Recommended for everyday use & power users.

ask-all

Maximum oversight. Read-only checks proceed freely, but every single write, move, or config alteration requires user confirmation.

Ideal for non-programmers and learning environments.

auto

Zero confirmation prompts for approved workflows. Hard-blocked destructive operations still refuse to run.

For automated scripts & isolated CI containers.
Deep Diagnostic Engine

Troubleshooting Cases: Guided Trial & Error

Got a stubborn hardware or network bug? (e.g., "Audio output switches to Dummy Output after reboot"). TermiAI starts an isolated Case:

  • 1 Pre-defines "Fixed": Establishes measurable pass/fail verification tests before touching any configuration.
  • 2 Isolated Trials: Tests hypotheses one at a time. If an attempt fails, it rolls back immediately before testing the next.
  • 3 Clean-Room Confirm: When a solution works, reverts all experimental steps and reapplies only the winning fix.
  • 4 Honest Outcome Reports: Distinguishes between verified fixes, workarounds, and documented upstream kernel regressions.
